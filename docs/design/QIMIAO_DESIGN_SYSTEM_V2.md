# QimiaoDaily Design System V2（草案）

状态：`APPROVED`（用户已批准）。这是 WPF 原生视觉与交互规范，不引入 Web 技术，不改变现有桌面架构。

## 设计定位

绮喵日报是“长期使用的桌面编辑工作台”，不是数据库管理后台。关键词：精致、轻盈、现代、二次元但不幼稚、信息清晰、有角色感。

## 视觉基础

- 背景：深石墨蓝黑；工作区用略亮的蓝灰层次，不用整页同色卡片。
- 主强调色：冷蓝紫只用于当前导航、主要操作和焦点；新增、验证、冲突、即将结束、已确定使用独立语义色。
- 边界：优先留白、分隔线和轻量底色，减少粗边框；卡片圆角不超过 8px，确有 framed tool 时才使用更大圆角。
- 阴影：WPF 低强度阴影只用于 Drawer/Dialog，不给每个列表行加阴影。

## Typography

| 级别 | 建议字号 | 用途 |
| --- | ---: | --- |
| Page Title | 26-30 | 当前页面标题 |
| Section Title | 17-20 | 审核区、确定区、工具组 |
| Item Title | 14-16 | 活动/角色标题 |
| Body | 13-14 | 描述与操作提示 |
| Metadata | 11-12 | 来源、时间精度、抓取时间 |

保证 1080p、125% Windows Scaling 下中文不截断；不使用随视口缩放字号。

## Spacing、Radius、Elevation

- 基础间距 4px；常用节奏 8/12/16/24px。
- 页面边距 24px，主栏间距 16px，紧凑行内边距 10-12px。
- 列表行高度目标 88-124px，随标题换行受约束，不使用巨大固定卡片。
- Radius：输入和按钮 4px，列表行 6px，Drawer/Dialog 8px。

## 组件

- Navigation：图标 + 中文标签，分为概览、内容、日报、系统；当前项用背景条和主色指示。
- Toolbar：页面标题、最后刷新、主刷新按钮、相关状态计数和过滤器在同一工作流内。
- Button：主要动作使用图标+中文，确认/危险/次要动作有明确语义色；熟悉动作优先使用图标按钮并提供 Tooltip。
- Filter：游戏、类别、审核状态和关键词；显示中文选项，内部值只在 ViewModel/数据库层存在。
- Badge：只显示有意义的状态；空值和 `NONE` 隐藏。
- Activity Row：游戏/类别/新增标记 → 标题 → 开始/结束 → 剩余状态 → 来源与验证 → 证据/确认动作。
- Artwork Card：图片优先，元数据收敛到两行，审核状态和选中日报动作清晰。
- Evidence Drawer：标题为“来源证据”，显示开始/结束时间来源、原始表达式、来源 URL、验证、抓取时间和 Revision；技术字段折叠。
- Empty/Loading/Error：分别显示“暂无待审核内容”“正在刷新… ”“刷新失败：原因”；不使用 `—` 掩盖未知。
- Status Bar：显示本地数据库正常、最后刷新和非阻塞提示；SQLite 不做大卡片。

## 时间和中文映射

- 游戏：`GENSHIN` 原神，`STARRAIL` 崩坏：星穹铁道，`NTE` 异环，`HI3` 崩坏3。
- 类型：`EVENT` 活动，`GACHA` 卡池，`ENDGAME` 周期挑战，`VIDEO` 视频，`PREVIEW_NOTICE` 前瞻预告，`PREVIEW_LIVE` 前瞻直播。
- 审核/验证：`PENDING` 待审核，`CONFIRMED` 已确定，`ARCHIVED` 已归档，`UNVERIFIED` 未验证，`CONFLICT` 来源冲突，`VERIFIED_OFFICIAL` 官方来源已验证，`VERIFIED_MULTI_SOURCE` 多来源已验证。
- 任务：`IDLE` 空闲，`RUNNING` 正在运行，`SUCCEEDED` 成功，`FAILED` 失败；`Run Now` 显示“立即刷新”。
- 角色名必须使用 canonical 中文名；英文别名只保留在 Evidence/原始数据/调试信息。

## 页面骨架

- 游戏活动：标题 + 最后刷新 + 立即刷新游戏数据；状态条（待审核/已确定/今日新增/冲突）；过滤栏；审核/确定双栏。
- 美图分享：今日采集进度、待审核/已确定/重复过滤、采集今日美图。
- 生日审核：角色总数、生日已知、未知生日、待审核、最后同步；列表 + 点击打开编辑 Drawer。
- BGI 更新：两个仓库 commit、时间窗口、刷新 GitHub 更新。
- 来源健康：全部来源刷新、解析覆盖率、延迟、候选/解析/丢弃数、可能漏采。
- 任务调度：自动计划、历史、失败重试、高级诊断；普通用户无需进入此页刷新数据。

## 刷新反馈契约

业务页的刷新按钮必须显示可读的阶段状态，而不是只显示“成功”：

```text
正在刷新原神…
原神：发现 X 条，新增 X，更新 X，冲突 X
正在刷新星铁…
星铁：发现 X 条，新增 X，更新 X，冲突 X
正在刷新异环…
异环：发现 X 条，新增 X，更新 X，冲突 X
覆盖率异常：可能漏采，详情见来源健康
```

阶段失败时保留已经完成的其他游戏结果，并明确显示失败来源和重试入口。

## 数据可解释性

活动证据 Drawer 的第一层必须回答“开始时间和结束时间分别来自哪里”；相对表达式显示原文和精度，不把版本时间填入活动时间。生日候选必须显示游戏中文名、canonical 中文角色名、生日已知/未知、来源等级和审核状态。

## 动效与可访问性

- 只对刷新、Drawer 打开、状态变化使用 120-220ms 过渡；禁止持续装饰动画。
- 所有图标按钮有 Tooltip，焦点状态可见，危险操作与确认操作可区分；文本在窄宽度换行而不遮挡相邻内容。
