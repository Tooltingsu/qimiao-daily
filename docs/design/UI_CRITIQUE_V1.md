# 绮喵日报 UI Critique V1

对象：2026-08-16 运行截图 `artifacts/screenshots/final/01-dashboard.png`、`02-game-review.png`、`09-calendar.png`、`14-scheduler.png`。这是旧版 BEFORE 审计，不是改版结果。

## 总体判断

当前界面已经有可用的左侧导航、深色主题和游戏审核/确定双栏，但整体视觉更像开发者后台：所有页面共享同一组统计卡、同一块大容器和同一套技术字段，导致长期使用时扫描成本高，业务重点不突出。

## 游戏活动页

- 页面顶端长期显示四个与当前页面无关的全局统计卡；游戏页真正需要的最后刷新、待审核、已确定、今日新增和冲突没有形成紧凑状态条。
- 条目标题上方直接显示 `NTEVIDEO · NONE`、`GENSHINEVENT · NONE` 等内部组合，用户必须先理解数据库枚举才能读懂内容。
- `PENDING`、`CONFIRMED`、`Evidence`、`Date only` 和 `Remaining —` 暴露实现细节；结束时间缺失没有说明原因。
- 活动行高度偏大，1440×900 的左右栏只能同时查看少量记录；滚动区域与卡片边界过重。
- “立即联网更新”存在，但刷新过程中没有按游戏/阶段展示进度和覆盖结果。

## 日历/生日区域

- 日历页仍重复全局统计卡，左侧月历与右侧自定义事件同时使用粗边框大容器，信息密度不均。
- 生日候选被放进日历页的长列表，角色英文名和内部 Franchise 值使中文工作流中断；缺少“角色总数/已知生日/未知生日/最后同步”的上下文。
- 编辑表单长期占据页面空间，应该改成点击后打开的 Drawer/Dialog。

## 调度页

- `IDLE`、`Last: -`、`Run Now` 和原始 `TaskKey` 对普通用户没有业务意义。
- 调度页看起来像普通刷新入口，而不是高级任务管理/失败重试/诊断页；与游戏、美图、生日页面缺乏直接刷新入口形成反向工作流。

## 导航、Header 和状态

- 左侧导航结构基本正确，但图标是重复菱形字符，当前项、分组和 hover 层次弱。
- 顶部 `本地 SQLite 已连接` 占据大块视觉空间，正常状态不应与业务内容争夺注意力。
- 顶部统计卡、边框、背景色和圆角重复使用，缺少页面级主次节奏。

## Cards、按钮、排版、颜色和密度

- Cards 都是大面积蓝紫矩形，状态颜色没有稳定语义；卡片内部技术元数据比标题和时间更抢眼。
- 按钮普遍是同形状文字矩形，动作优先级和危险操作区分不足。
- 页面标题和正文层级尚可，但中文正文在卡片中被元数据、URL 和枚举挤压。
- 深色主题可以保留，但需要石墨/蓝黑底、低对比分隔、单一主强调色和独立语义色，减少“所有区域都有边框”的后台感。

## 目标改进

保留 WPF、左侧导航和游戏页双栏；用页面相关状态条、过滤工具栏、紧凑活动行、中文显示映射、证据 Drawer、轻量 Status Bar 和业务页直接刷新构成“日报编辑工作台”。详见 `QIMIAO_DESIGN_SYSTEM_V2.md`。
